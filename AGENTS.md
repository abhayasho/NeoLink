# AGENTS.md

NeoLink is a native macOS (13+) SwiftUI/AppKit coding workspace: tabbed terminal + SSH/SFTP, shared Neovim editor, native ACP agents, Git review.

## Build & run
- `swift build` / `swift run` — debug executable from repo root.
- `./scripts/build-app.sh` — release `NeoLink.app` in repo root; copies `Resources/`, embeds `SwiftTerm_SwiftTerm.bundle`, precompiles Metal shaders when `xcrun metal` exists, then ad-hoc signs. Set `NEOLINK_SIGNING_IDENTITY` for stable signing. `NeoLink.app` and `.build/` are gitignored build artifacts.
- One executable module: everything under `Sources/` is the `NeoLink` target. The directory split (`Terminal/`, `Documents/`, etc.) is organizational only, so cross-folder `internal` access is normal. No `@main`; `Sources/main.swift` starts `NSApplication` directly.

## Verify
- `GlyphRasterizationTests` compares all 16 cached glyph phases with direct CoreText; preserve phase-aware atlas keys, integer-pixel quads, and stale-drawable size checks. Terminal display updates drain on the owning Metal callback, not two independent clocks.
- `swift test` — native regression tests, temporary files only; no SSH server or credentials needed. `SmoothScrollRenderingTests` renders with Metal and compares pixels (skips without a GPU).
- `swift test` also runs `NativeGridProtocolTests`, `NativeGridRenderingTests` (native-vs-terminal pixel equality, retained-row reuse, an edit plus status line rebuilding exactly 2 rows) and `NativeGridEditorTests` (real headless Neovim: ordering, leave/touch notices, end-to-end session). `NEOLINK_NATIVE_GRID=1 swift test` runs the whole suite against the native client.
- `python3 scripts/test-editor.py` — real Neovim runtime regression (also invokes the private-PTY multiline-error/duplicate-name check); requires `nvim` on `PATH`. Uses `Resources/Editor/neolink.lua` and checks buffers, saves, external conflicts, UTF-16/CRLF, large-file mode, optional Pyright LSP.
- `python3 scripts/test-benchmark.py` — offline build-failure/scroll-validity checks; does not launch the GUI.
- The project tree retains a reusable-row `NSTableView` for input, accessibility and fallback (`Sources/FileBrowser/ExplorerTableView.swift`). `ExplorerMetalView.swift` composes cached row artwork with Metal; CoreText rasterization runs off-thread. Folder List and SFTP retain their own views.
- Explorer Metal composition retains a native-resolution GPU strip (at most 16 MiB extra) with nearby rows; reuse only within its row range and matching row-content revision/backing scale/width. Hover/selection/active highlights draw a few replacement row quads after the opaque text strip; changing them must not rebuild that strip. Keep their visual revision separate and compare overlaps against the per-row reference. Preserve pixel equality with the per-row reference path and invalidate selection, hover, content and resize changes. Retire row-indexed GPU state before replacing table rows; empty/out-of-range native visible rectangles must still invalidate/wake the surface. Never index a new scene using unchecked retained strip bounds. Benchmark traces/profiling are opt-in.
- Covered explorer cells retain their accessibility/hit-testing identity but hide and defer native artwork; restore the latest artwork on fallback. Precise unmodified trackpad deltas use `ExplorerScrollView` while Metal covers the table; other events retain AppKit behavior. Surface-owned animations advance in `prepareDrawable`, after parsed output and before encoding, with native-clock fallback.
- Reveal revisions are issued when navigation is requested, before asynchronous ancestor loads. A later scroll or explicit tree navigation cancels the pending reveal; visible rows stay stationary and offscreen rows move to the nearest edge.
- Explorer raster work stays bounded to 16 jobs on the serial worker. Prefetch nearest neighbors first; cancel stale unfinished work after disjoint viewport jumps, retaining valid cached artwork.
- Tab-strip geometry depends on names/paths, never hover, selection or modified state. Native horizontal scrolling reveals only the nearest edge. Duplicate basenames use the shortest distinct parent suffix.
- `NEOLINK_SELECTION_TRACE=1` adds bounded per-generation events to `ui-tabs`; a file path instead of `1` writes events on quit. Editor hrtime is explicitly mapped to host monotonic time with round-trip uncertainty. Keep focus and acknowledged-buffer presentation separate.
- PTY trace chunks are stamped on the background reader and at admission/delivery/parse; join the recognized marker's chunk ID across selection generations. `NEOLINK_PREPARATION_PROFILE=1` collects row-stage CPU diagnostics separately from unprofiled comparisons. Hidden Metal panes and external-owner callbacks without a supplied drawable/texture must return before row preparation or consuming dirty state/tags. Empty glyph keys cache only confirmed zero ink, never transient failures; glyph caches use interned font ids and every id-keyed cache must be cleared together if ids are reissued. Tab-strip text measurement is memoized; keep it a pure function of names/paths.
- Explorer snapshots coalesce during live scrolling/momentum and apply after 100 ms of quiet; explicit navigation takes precedence. Local shell scrollback preserves its fractional position at rest; full-screen program scrolling retains the grid-alignment model. Metal presentation keeps VSync enabled, including immediate key echoes.
- ACP blocking pipe reads run on dedicated dispatch queues with bounded main-thread handoff; never move blocking reads onto Swift’s cooperative task executor. The CI constrained-pool check invokes xctest directly (setting the strict-pool variable on SwiftPM itself can stall SwiftPM). ACP tests launch the offline fixture `scripts/fixtures/acp-agent.py` via `python3`.
- GitHub Actions runs native, editor-runtime and offline benchmark tests plus release packaging and `scripts/verify-app.py`. On-screen cadence remains a local release check; CI does not establish 120 Hz smoothness. No linter or formatter config exists.
- Rendering/latency changes: run the interaction benchmark (`NEOLINK_BENCHMARK=...`, see `docs/RENDERING.md`) on a release build with the window frontmost and the screen unlocked; an occluded window pauses its clock and invalidates the run.
- `NEOLINK_BENCHMARK=render-motion` animates both terminal scrollback and the Metal explorer without input injection; it reports actual presented content changes. Offscreen `ExplorerMetalTests` verify pixels even when the screen is locked, not on-screen cadence. Surface Metal callbacks run separately from the window clock; do not reintroduce whole-window display passes or fetch MTKView drawables while a Metal display link owns the layer.

## Architecture wiring
- `Sources/main.swift` creates the `WorkspaceWindow` + `WindowFrameScheduler` (frame pacing, capped at 120 Hz); `Sources/ContentView.swift` composes sidebar, file browser, tabbed terminals, and right agent panel.
- `Sources/Tabs/TabsController.swift` owns all workspace tabs (`WorkspaceTab`: terminal or document) and the single shared `NeovimSession`. The selection is published by `TabSelection` (`controller.selection`), not by the controller: views that show it observe it (tab strip/panes, editor toolbar, explorer active file, footer, agent context), and the controller publishes `browserTabID` only when the shown browser changes. Keep selection off the controller's `@Published` state; a switch otherwise re-evaluates the workspace root and its layout (~15 ms before the next frame). Tab buttons take `isSelected` by value.
- `Sources/Documents/NeovimSession.swift` lazily starts one Neovim per app in `/tmp/neolink-*`, uses a persistent, bounded newline-JSON private Unix control socket plus coalesced off-main `status.json` reads, and uses `Resources/Editor/neolink.lua`. Missing `nvim` degrades to the native text editor. Queue commands synchronously before waiting for startup; only obsolete selection-only work may be skipped, not saves/closes/initial opens. Warm idle selections enqueue directly to the ordered socket worker before UI layout; retain queue barriers for all other commands. Keep asynchronous service errors nonblocking (`messagesopt`), retain `:messages`, and publish the bounded UTF-8-safe notice to the native banner. Selection generations gate snapshots/focus and a post-redraw TUI marker gates visibility. Never write raw bytes to Neovim stdout (it may be split-TUI RPC); use `nvim_ui_send` or native title events on older versions. In `neolink.lua`, never read or set a hidden buffer's options through `vim.bo[buf]` on a hot path (open, snapshot, autocmds): it switches context and forces a full redraw of the screen (5–11 ms); read with `getbufvar()` and set only what differs.
- Workspace presentation is direct by default (`NeoGPUDirectFrameSource`: window `CADisplayLink` + `nextDrawable()` + present on commit, ≤2 drawables waiting, never request a drawable while shown frames go unacknowledged); `NEOLINK_PRESENTATION=link` restores `CAMetalDisplayLink` for same-binary comparisons. Do not reintroduce a target-time pipeline several refreshes ahead: it added ~10–17 ms to every interaction (`docs/RENDERING.md`).
- Custom workspace GPU engine: `Sources/Rendering/NeoGPU/` owns retained instanced scenes, pixel clipping, shared resources and one macOS 14+ display-link deadline/drawable/command buffer/presentation for visible terminal/editor and explorer panes. The independent window clock pauses during hosting. The workspace presents a drawable only when what it would show differs (`NeoGPUNode.changed`, a different scene/position/clip/size, a dropped drawable, a reconfigured layer); an idle workspace presents nothing. Keep the two measured exceptions: every refresh is presented while a pane reports `needsAnotherFrame` (the slack absorbs heavy motion frames), and after input retained content repeats only while `NeoGPUDirectFrameSource.isQueueEmpty`. `QueuedDrawables` drains a standing queue only at 3.2+ periods from acquisition to display; draining at two periods and presenting nothing after input were both measured and rejected (`docs/RENDERING.md`). A pane that draws into a texture its scene keeps must set `changed`, or its update is never shown. Continuous High Refresh (off by default, saved in the View menu) presents every refresh; occluded/minimized windows pause. Native views retain input/accessibility; Quick Open/Git overlays temporarily restore independent rendering. `NEOLINK_GPUI_WORKSPACE=0` selects the independent path for same-binary release comparisons. Native panels/PDFs are not rewritten.
- GPU rendering: `Sources/Terminal/TerminalRendering.swift`, `Sources/Rendering/NeoGPU/NeoGPUFrameSource.swift` + `Sources/Rendering/WindowFrameScheduler.swift` (display-link pacing, immediate frames for typed output, presentation backpressure, latency stats), persisted View-menu preference. Trackpad smooth scrolling: `Sources/Terminal/SmoothScroll.swift`. SwiftTerm's Metal bundle must be present in packaged apps.
- Native Neovim UI client (default; TUI-in-PTY is the fallback, `NEOLINK_NATIVE_GRID=0` or View → Native Editor Rendering selects it, `=1` forces native; `open` does not pass shell variables): `Sources/Documents/NativeGrid/` (msgpack, RPC connection, `NeovimGridModel`, `NeovimGridClient`, `NativeGridPresenter`, `GridSnapshotCache`, `NeovimKeyEncoder`) attaches an `ext_linegrid` UI to a headless `nvim` and writes rows into the editor's SwiftTerm buffer through the `externalGrid*` hooks (`Vendor/SwiftTerm/UPSTREAM.md`). Decode and grid application stay on the reader queue; the main actor only drains the mailbox (display deadline plus one coalesced wake). Visibility keeps the same correctness rule as the OSC marker: `neolink.lua` sends `neolink_selection` over the ordered UI channel after the buffer-enter `redraw`, the presenter writes rows first, then `NeovimSession` applies the generation check; never show a cached image unless `GridSnapshotCache.validEntry` conditions (untouched buffer, size, style epoch, diagnostics flag, file signature, insert mode without popup) hold, never let input reach a speculative image (it queues), and never write rows from a frame whose size differs from the terminal. Keep `neolink_leave`/`neolink_touch` and `winrestview` in sync with the cache rules. See `docs/NATIVE_GRID.md`. Rows the client writes through the `externalGrid*` API are marked exactly (`markingExternalRows`), so the renderer rebuilds only them rather than the span between the edited line and the status line; keep external marks inside it.
- Horizontal editor scrolling (native client) is pixel-smooth: `NativeHorizontalScroll` asks `NeoLink.hscroll` for leftcol chunks ahead of the fingers, holds frames until the ordered `neolink_hscroll` answer, detaches (never overwrites) the rows of the previous chunk, and sets `TerminalView.externalHorizontalScroll` (gutter fixed, text band translated in whole device pixels, retained layers preferred, current rows built on a per-frame budget). Sessions end on a whole column before any key, click, vertical scroll, selection change or resize. `NEOLINK_HSCROLL=0` restores column steps. Keep `NativeGridRenderingTests` band pixel equality and the real-Neovim horizontal test passing.
- Trackpad gestures lock to their dominant axis (`ScrollAxisLock`, Zed's thresholds: 28 ms, 6 pt, 1.9×) before any wheel reaches a program; never forward sideways drift of a vertical gesture to Neovim (each column redraws every row). The explorer's `ExplorerScrollView` glides through `ScrollResampler` at display cadence; programmatic scrolls cancel the glide.
- Trackpad scrolling (`Sources/Terminal/SmoothScroll.swift`): `ScrollResampler` draws the accumulated input interpolated at the display's cadence (`drawn offset = model offset − lag`); whole-line grid moves must not change `lag`, clamped input must be `absorb`ed, and it must stay on the display-link animation callback (no timers). Measure the input interval from every event (even after catching up), keep the delay a continuous function of it with a bounded slew (`delaySlew` < 1 never samples backwards), and feed events' sampling times (`scrollInputTime`). `ScrollResamplerTests` cover uniformity, jitter, reversal, end clamping, a slower stream after a fast gesture, 80 Hz input without held frames, delay continuity and rate changes. `TabSelectionTests` checks that switching documents publishes only the selection. See `docs/RENDERING.md`.
- Pane switching: `TabsController.selectedTabID` shows/hides the terminal pane itself (`switchPanesNow`, `TerminalHostView.synchronize(immediate:)`) and the newly visible pane is drawn at once with `NeoGPUWorkspace.presentNow()` (direct frame source only; same layer and queue bound; `NEOLINK_IMMEDIATE_SWITCH=0` disables it). SwiftUI's later update must be a no-op for the pane. Keep the covered terminal + status bar (`shownTerminalTab`) and the editor toolbar (`shownEditorDocument`) mounted so a covered pane never changes size on selection; a covered pane must never take focus. Gate panes with `PaneGate` (z-order), not `allowsHitTesting`: toggling it re-parents the native views and bumps the workspace generation on every switch. `TabStripButtons` observes its own models; do not replace the strip's hosted root on update. Covered panes defer grid resizes (`CoveredPaneResize`, 150 ms quiet, applied on show).
- `DeferredPresentations` defers only content acknowledgements (`NeoGPUNode.acknowledged`), matched by pane and frame order; never replay `presented` (ownership, position samples) for a dropped drawable or run it for a stale generation.
- `LayoutTrace` (with `NEOLINK_SELECTION_TRACE`) records `body.*`/`layout.*`, `main.busy` spans, `link.tick` and `ws.draw`. Profile a build with `xctrace --attach`; `--launch` on `.build/release/NeoLink` starts the installed app instead.
- Agents: ACP transport/session in `Sources/Agents/ACPTransport.swift` and `ACPSession.swift`; terminal agents use `CodingAgent`/launcher. See `docs/AGENT_GUIDE.md`.
- Project access uses security-scoped bookmarks in `Sources/Workspace/WorkspaceAccess.swift`; Git review is `Sources/Workspace/GitChanges*` and explorer decoration is `Sources/FileBrowser/ExplorerGit.swift`.

## Repo-specific constraints
- `Package.swift` intentionally uses `swift-tools-version: 5.10` (Swift 5 language mode) to avoid Swift 6 concurrency conflicts with `swift-ssh-client`. Don't bump it casually.
- SwiftTerm is a pinned local snapshot (`Vendor/SwiftTerm`, v1.20.0), not a normal remote package. NeoLink changed its frame scheduling, Metal renderer (row cache by line identity, smooth-scroll region, shared shaders, a `float4` viewport uniform in `Shaders.metal`) and region-scroll reporting in `Terminal.swift`; `Vendor/SwiftTerm/UPSTREAM.md` lists every change. Read it before updating and reapply/test them.
- `Resources/` is not a SwiftPM resource target. Code falls back to `#filePath`-relative paths; `scripts/build-app.sh` must copy `Resources/Editor` and the SwiftTerm bundle for a packaged app to work.
- Resource limits are deliberate: >2 MiB files skip LSP/Tree-sitter, code tabs cap at 128 MiB, SFTP remote previews are read-only. See `docs/CODING_WORKSPACE.md`, `docs/RENDERING.md`, and `docs/EXPLORER.md` for behavior worth preserving.
- Ad-hoc rebuilds can change app identity and re-trigger macOS folder permissions; bookmark behavior depends on consistent signing.
